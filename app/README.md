# estama-tracker（プロトタイプ）

エステ魂（estama.jp）で、大阪の「普段は完売なのに今日・明日空いているキャスト」を
見つけるための、ローカル履歴DBプロトタイプです。

## 目的

- 「普段完売なのに今日空いてる！」「明日空いてる！」を、1日の表示だけではなく
  過去の完売履歴と比べて拾うこと。
- そのためには毎日スナップショットをためる必要があり、本ツールはそのための
  パーサー＋SQLite DB＋アラート判定を提供します。

## 重要：ウォッチリストのスコープ変更（2026-10-26）

- **最終ウォッチリストは、大阪の口コミ件数順トップ20ではありません。**
  2026-10-26のスコープ変更により、最終ウォッチリストは
  **大阪の口コミ件数が多い順の20店舗** になります。これは別途収集予定です。
- `shops.json` がそのウォッチリスト設定ファイルです。現時点では空欄（PENDING）で、
  収集が終わるまでは最終ウォッチリストは存在しません。
- `sample_2026-10-26_top20.json` は、大阪の一覧順トップ20（2026-10-26 16:09-16:14 JST
  収集）のサンプルファイルです。**サンプルであり、最終結果ではありません。**
  トップ20の件数を最終プロトタイプの結果として提示してはいけません。
- ライブの一覧順は時間で変わるため、将来も「毎回トップ20を再導出」はしません。
  ウォッチリストは `shops.json` に固定して使います。

## ファイル構成

- `shops.json` — ウォッチリスト設定。`shops` に店舗ID・名前・エリア・URLを入れる。
  空の間は最終ウォッチリスト未設定。
- `sample_2026-10-26_top20.json` — サンプル用スナップショット（トップ20、サンプルのみ）。
- `snapshot_<日付>.json` — 将来のスナップショットも同じ形式で置く（下記「形式」参照）。
- `schema.sql` — SQLiteスキーマ。
- `estama_tracker.py` — 取り込み・照会・アラート判定（Python標準ライブラリのみ）。
- `estama.db` — 最終ウォッチリスト用DB。`shops.json` が埋まってから作る。
- `estama_sample.db` — サンプル用DB。最終DBとは別ファイル。

## 完売の判定ルール（最重要）

- 完売は、セラピスト単位のステータス文言からのみ判定します。
  - `ご好評につき本日完売` → `sold_out`
  - `受付終了` / `本日受付終了` → `closed`（完売とは別扱い）
  - `残りわずか` → `low`
  - `今すぐご案内` / `ご予約受付中` → `available`
  - `時間のみ` / 不明 → `unknown`
- 時間帯表の記号 ○/×/─ は補助テキストとして保存するだけで、
  **完売の判定には絶対に使いません**。大阪は ○/─ だけの店舗が多く、
  完売なのに ○ が残る例もあるため、×で完売を決めると循環論法になります。
- 店舗単位の「満員御礼」も、キャスト個人の完売とは別扱いです。

## キーと重複の扱い

- v1のキーは `(shop_id, cast_name, target_date)` です。表示テキストに
  キャストIDがなかったため `cast_id` は null です。将来、表示から
  キャストIDが取れるようになれば、キーに加えてください。
- 同じキャスト名が複数店舗に出ても、店舗ごとに別行として扱います。
  特に YOLU SPA の各ルームは店舗IDが違うため、重複除去しません。
  サンプルでは YOLU 系が7店舗分、別々の shop_id 行になっています。

## スナップショット形式（将来の差し替え用）

将来の口コミ順スナップショットは、サンプルと同じ形式で置くだけで
コード変更は不要です：

```json
{
  "snapshot_date": "2026-10-27",
  "collected_jst": "2026-10-27 16:00-16:10",
  "shops": [
    {
      "shop_id": 12345,
      "name": "店舗名",
      "area": "エリア",
      "store_status": "◎今すぐご案内可",
      "source_url": "https://estama.jp/shop/12345/schedule/",
      "has_table": true,
      "casts": [
        {
          "cast_name": "名前",
          "cast_id": null,
          "age": 25,
          "shift": "12:00～22:00",
          "status_raw": "ご好評につき本日完売",
          "slot_pattern": "○／×／─"
        }
      ]
    }
  ]
}
```

- `has_table: false` の店舗は `casts: []` にします（出勤表がない店舗）。
- 出勤表は最初のページ（最初の7人まで）のみを対象とします。
  2ページ目以降は v1 では対象外です。

## 使い方

```bash
cd ~/workspace/estama-tracker

# ウォッチリストの状態確認（現時点では PENDING と出るはず）
python3 estama_tracker.py status

# サンプルだけを別DBに取り込んで、パーサーと照会を試す（最終DBではない）
python3 estama_tracker.py sample
python3 estama_tracker.py sold-out --date 2026-10-26 --db estama_sample.db
python3 estama_tracker.py counts --date 2026-10-26 --db estama_sample.db

# 口コミ順スナップショットができたら（shops.json に20店舗を入れてから）
python3 estama_tracker.py load snapshot_2026-10-27.json --shops shops.json
# --shops を付けると、ウォッチリスト外の店舗は取り込まず、件数を報告します。

# 履歴がたまってからのアラート判定
python3 estama_tracker.py alert --date 2026-10-30
python3 estama_tracker.py alert --date 2026-10-30 --min-snapshots 3 --threshold 0.7

# アラート判定ロジックの単体テスト（メモリ上のみ、DBに保存しない）
python3 estama_tracker.py demo
```

## アラート判定の定義

- 対象日より前のスナップショットだけを履歴とします（対象日自身は含めません）。
- 履歴が `MIN_SNAPSHOTS` 件以上（既定3件）あり、そのうち完売の割合が
  `threshold` 以上（既定0.7）で、対象日のステータスが `available` または
  `low` のキャストをアラートします。
- `sold_out` / `closed` / `unknown` のままのキャストはアラートしません。
- 履歴が足りない場合は、アラートは空で「履歴不足」と明示します。
  履歴をでっち上げてアラートを出すことはしません。

## 制限事項（v1）

- **v1 はライブサイトの自動ポーリングをしません。** スケジュール実行での
  自動取得は未実装です。スナップショットはブラウザで収集したものを
  JSONとして取り込む方式です。自動化する場合は、取得間隔・負荷・
  サイトの利用規約を別途確認してからにしてください。
- ログイン・予約操作・電話発信は一切しません。公開表示の確認と保存のみです。
- 出勤表は最初のページのみです。2ページ目以降のキャストは含まれません。
- キャストIDは null で、キーは店舗＋名前です。同名の別人がいる場合は
  区別できないため、将来はキャストIDの導入が必要です。
- 表示は時間で変わります。スナップショットはあくまで収集時点の表示です。
- サンプルファイルの既知の欠落：下記「サンプルの既知の欠落」を参照。

## サンプルの既知の欠落（重要・隠さないこと）

サンプルファイル `sample_2026-10-26_top20.json` は、元のブラウザ報告書で
「20店舗・出勤表のある店舗のキャスト124人・出勤表なし1店舗・完売3人」と
されていたデータのうち、サブエージェントの手元に残っていたのは
店舗ID・店舗名・エリアと、完売3人（下記）のみでした。保存されていた
出勤表スクリーンショットは画面上部のみで、キャスト行は画面外だったため、
残り121人分のキャスト行はローカルから復元できませんでした。

- そのためサンプルファイルのキャスト行は3行のみで、124行ではありません。
  **サンプルDBのキャスト件数（3）を、元の報告書の124と混同しないでください。**
  欠落分を補うためにキャスト名・年齢・シフト・ステータスを創作していません。
- 検証できるサンプル側の件数：
  - 店舗数：20（一致）
  - 出勤表なし店舗：1（YOLU SPA 大阪店 心斎橋エリア、48159、一致）
  - 完売：3（下記、一致）
  - 出勤表のある店舗のキャスト行：ファイル内は3行のみ（元報告書は124行、**不一致・欠落あり**）
- 完売3人（サンプル内で検証済み）：
  - Queen Spumante ークイーンスプマンテー（31933）— 七瀬ことみ
  - Queen Spumante ークイーンスプマンテー（31933）— 深田みゆ
  - ぷちどり～む（41036）— まみ
- サンプルで `store_status` が入っているのは、スクリーンショット上部で
  確認できた Queen Spumante のみです。他店舗は null（未確認）です。

## まだ必要なもの（口コミ順への移行）

1. 大阪の口コミ件数順トップ20店舗の特定と、その出勤表スナップショットの収集
   （ブラウザでの収集が必要。サブエージェント単体ではライブ閲覧はできません）。
2. そのスナップショットを上記形式の JSON として保存すること。
3. `shops.json` の `shops` にその20店舗を入れること。
4. `python3 estama_tracker.py load <新スナップショット>.json --shops shops.json`
   で最終DB（`estama.db`）を作り、件数を検証すること。
5. 数日分のスナップショットがたまってから初めて、アラート判定が意味を持ちます。
   初日は「履歴不足」でアラートは空になります。

## スクレイピング自動化と完売スピード分析（estama_scraper.py）

店舗（例: 梅田高級メンズエステ SUPER AKUMA GIRLS）のスケジュールを自動取得し、
取得時刻ごとの時系列ログ（1日12回）を保存して「完売スピード分析」を行うツールです。

### 実行時間の目安（1日12回・約2時間おき）
「早く売り切れるキャストほど人気」であるため、以下の12チェックポイントでの蓄積を推奨します：

- `00:30`, `03:00`, `05:00`, `07:00`, `09:00`, `11:00`
- `13:00`, `15:00`, `17:00`, `19:00`, `21:00`, `23:00`

### 出勤終了（受付終了）と完売の判別ルール（重要ノウハウ）

出勤シフト（例: 12:00～16:00）が終わると、ステータスは自動的または手動で「受付終了（closed）」に切り替わります。
このとき、夜間に1回だけスクレイピングすると以下の2つのパターンがどちらも「受付終了」に見えて判別できません：

1. **【完売終了（人気）】**: 昼に「本日完売」になり、全枠の施術を終えて16:00に「受付終了」になった。
2. **【売れ残り終了（不人気）】**: 空き枠（○）のまま誰も予約が入らず、シフト終了時間を迎えて「受付終了」になった。

#### 判別方法（チェックポイントDBログの参照）:
- 1日12回（約2時間おき）の時系列チェックポイントを蓄積しているため、**「シフト時間中（終わる前）のレコード」** を参照します。
- **その日の出勤中に1度でも `sold_out`（本日完売）が記録されていれば、最終的に `closed`（受付終了）になっても「その日は完売」と判定します。**
- シフト時間終了直前まで `available`（空き）のまま受付終了になった場合は、「売れ残り時間切れ終了」として完売には含めません。
### 出勤シフトの分解と勤務時間の自動算出（人気度判定の重み付け）

出勤シフト（例: `12:00～20:00`）を自動分解し、勤務時間を算出してDBに保存します。
- `shift_start`: 開始時刻（例: `12:00`）
- `shift_end`: 終了時刻（例: `20:00`, 日またぎ `25:00`）
- `work_minutes`: 勤務分数（例: `480` 分）
- `work_hours`: 勤務時間（例: `8.0` 時間）

#### メリット:
- **勤務時間の長さに応じた完売難易度の比較**:
  - `3.0h`（ショートシフト）で完売したのか、
  - `11.5h`（ロングシフト）で完売したのかを客観的に比較可能。
  - ロングシフトなのに即完売するキャストほど、圧倒的な予約枠数を埋めている「真の超人気キャスト」と判定できます。
- 空きキャストが複数いた場合にも、「残り勤務時間の長さ」を考慮して比較・選択できます。

### コマンド例
```bash
# 1. 取得・スナップショットJSON保存・DBへの時系列蓄積
python3 estama_scraper.py --shop-id 40900 --days 1 --save-snapshots --import-db

# 2. 完売スピード分析（誰が何時に完売したかランキング ＆ 時系列推移表）
python3 estama_scraper.py --speed-rank --date 2026-10-26

# 3. cron設定ガイドの表示
python3 estama_scraper.py --cron-guide
```

## 週間人気セラピストランキング取得（ranking_scraper.py）

エステ魂のセラピスト人気ランキング（週間TOP30）を定期取得し、人気キャスト情報（順位、年齢、カップ、所属店舗）を `cast_rankings` テーブルに保存します。

### エリア構成
- **大阪府全体（総合TOP30）**: `https://estama.jp/kansai/ranking/therapist/2700/weekly/`
- **梅田・大阪駅（TOP30）**: `https://estama.jp/kansai/ranking/therapist/2701/weekly/`
- 他、注目全13エリア（難波:2704, 日本橋:2703, 心斎橋:2702, 京橋:2706 等）対応

### コマンド例
```bash
# 梅田・大阪駅の週間TOP30を取得してDB保存
python3 ranking_scraper.py --area 2701 --import-db --save-json

# 大阪府全体の総合TOP30を取得してDB保存
python3 ranking_scraper.py --area 2700 --import-db

# 大阪全13エリアを一括巡回して全人気キャストを保存
python3 ranking_scraper.py --area all --import-db

# 上位ランクインキャストの所属店舗をウォッチリスト（shops.json）に自動同期
python3 ranking_scraper.py --area 2701 --sync-watchlist
```
